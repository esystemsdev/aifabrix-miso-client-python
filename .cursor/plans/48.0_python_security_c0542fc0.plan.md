- `5) Use of exit() or quit()` (`2`) detail (from provided screenshots):
  - Theory:
    - `exit()` and `quit()` are convenience objects from `site.py` (`site.Quitter`), not guaranteed in all interpreter modes.
    - They can be absent when `site` is not loaded or modified, so production/runtime code should avoid relying on them.
    - `sys.exit()` is stable and interpreter-guaranteed for process termination semantics.
  - Fix approach:
    - Replace `exit()` / `quit()` with `sys.exit(<code>)`.
    - Add/import `sys` explicitly in modules where replacement is made.
    - In test scripts, prefer returning status codes from main function where feasible; use `sys.exit` only at process boundary.
  - Best practices:
    - Avoid direct interpreter helpers in SDK/library internals.
    - Keep termination logic explicit and localized (CLI/test runner entrypoint), not deep in reusable functions.
    - Preserve exit code behavior when replacing calls (`0`/non-zero semantics must remain unchanged).
    - Validate with test execution that CI and local scripts still report expected pass/fail status.

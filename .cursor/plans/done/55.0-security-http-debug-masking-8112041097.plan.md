### Revised behavior and minimal implementation

- Retain `value` in packaged and fallback sensitive-field defaults. Match it only when the complete field name normalizes to `value`; normalization remains lowercase with `_` and `-` removed, so `VALUE` and `v_a_l_u_e` are exact matches. The `value` token alone must not mask `totalValue`, `defaultValue`, `values`, `valueCount` or `evaluation`.
- Preserve the existing precedence: normalized `neverMaskFields` first, then exact sensitive-field equality, then substring matching. In the substring loop only, skip the normalized sensitive token `value`. Apply this same source-neutral rule to packaged defaults, hardcoded fallback, global custom configuration and per-call explicit configuration.
- Other sensitive tokens keep existing matching behavior. A field such as `secretValue` remains masked because `secret` independently matches. Do not introduce an allowlist of benign fields, a new configuration schema/switch, a second masking engine, or a broad matcher refactor.
- Preserve currently supported custom configuration semantics: `mergeWithHardcodedDefaults`, `neverMaskFields`, `substringMinLength`, `fields`, explicit config paths and fallback loading. If a custom `fields` entry explicitly lists `totalValue`, it masks by exact equality; if it intentionally places `value` in `neverMaskFields`, that existing override remains authoritative. A nonempty `mergeWithHardcodedDefaults: false` configuration that omits `value` continues not to inherit it.
- Python currently exposes `fieldPatterns` through its loader but `DataMasker` does not consume those entries. Preserve that SDK difference: this amendment must not activate, merge, reinterpret or test `fieldPatterns` behavior.
- Ordinary-route composite fields are not presumed secret. If a deployment stores sensitive content under a composite name such as `totalValue`, it must list that complete field (or another independently matching sensitive token) in its configuration. Security endpoint bodies retain unconditional omission before masking.

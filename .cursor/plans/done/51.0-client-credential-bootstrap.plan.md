# 51.0 Client credential bootstrap (Python)

## Approved implementation scope

The user approved implementation and then clarified that this client must contain no provider-specific
code or references. The SDK knows Miso credentials, the Miso controller and opaque configuration
values. Hosting, provider identity and secret provisioning belong outside the SDK. This correction
supersedes the original plan's legacy provider reserved keys and article-path retention.

Use `MISO_AUTH_MODE=client-credentials` for remote bootstrap. Supply `MISO_CONTROLLER_URL`,
`MISO_CLIENTID` and `MISO_CLIENTSECRET` through deployment. Default `local` mode stays unchanged.
The first exchange mints a token; bootstrap and refresh use `x-client-token`. The snapshot retains
its closed nine-field shape and existing clock, size, confidentiality and failure guarantees.

Scope: bootstrap initialization, isolated transport, runtime token handoff, snapshot parsing,
public exports, dependency metadata, bootstrap tests, documentation and release metadata.
The Miso 257.0 controller implements the snapshot endpoint; deploy it before enabling this mode.

## Rotation

The implementation mints once per new runtime, then authenticates each refresh with the
last **validated and installed** snapshot's `clientToken`. Refresh remains jittered at 110–120s.
The runtime installs snapshot tokens into `BrokerTransport` only after validation and identity checks. Never call `runtime.get_token()` from the
bootstrap transport: it can recursively enter the same refresh task.

Credential rotation alone does not require restarting a healthy runtime while its token chain
continues to be accepted. This is conditional on server token validity, not a guarantee that
revocation or an outage can be survived. Ordinary API use still observes the snapshot token's
advertised deadline minus 30s. For bootstrap recovery only, the retained snapshot token may be
presented until the snapshot secret deadline minus 30s; Miso 257.0 currently issues a 900s JWT
while advertising a 300s client-token lifetime. Test this distinction against the controller.
Never extend ordinary API token validity or serve expired secrets.

`authorization-denied`, `protocol-error` and `snapshot-expired` are terminal. The current
`ensure_active()` gate prevents refresh after invalidation; it does **not** re-mint credentials.
Preserve that behavior. Close the failed runtime and initialize a new one with current deployment
credentials (normally via process restart). Do not automatically re-read environment variables,
re-mint after denial, or fall back to local mode. No new snapshot field is needed, and
`MISO_CLIENTSECRET` remains reserved.

## Overview

Development/security change owned by the Platform (Miso) Python SDK. Replace only the opt-in
provider-specific authentication path, retaining default `local` behavior and the closed snapshot
contract. The sibling TypeScript working tree now also uses `client-credentials` and the same
eight reserved keys. Source agreement does not prove deployed availability; coordinate rollout with Miso 257.0.
